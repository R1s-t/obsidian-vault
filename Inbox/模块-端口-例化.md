# 模块、端口与例化

## 一句话

`module ... ( ... );` 只是**名字加引脚清单**，`endmodule` 才是句号；中间那一大片才是描述电路的地方。

## 为什么需要它？

因为 Verilog 的结构部分只有三件事，而初学者最容易在"边界在哪"上卡住：

1. 定义一个模块（图纸）
2. 声明内部的线（导线）
3. 例化别的模块（摆器件、接线）

搞不清 `module` 的括号是什么意思，就会以为"模块到 `);` 就结束了"，后面所有代码都读不懂。

## 直观理解

Verilog 用 `module ... endmodule` 代替 C 语言的花括号：

```c
void foo(int a, int b) {     // 括号是参数
    int x = 1;               // 函数体
}                            // 花括号结束
```

```verilog
module foo (input a, input b);   // 括号是端口
    wire x;                      // 模块体
endmodule                        // endmodule 结束
```

**`);` 等价于 C 里那句 `) {`——它开启模块体，不是关闭模块。**

## 模块的完整骨架

```verilog
module 名字 ( 端口列表 );     ← 头：名字 + 引脚清单

    // ── 声明区 ──
    wire c1, c2, c3;
    reg  [7:0] tmp;
    parameter WIDTH = 8;

    // ── 描述区 ──
    assign sum = a ^ b;
    always @(posedge clk) ...;
    子模块名 u0 (...);        // 例化也在描述区

endmodule                    ← 尾
```

模块体里的条目分五类：

| 类别 | 例子 | 备注 |
|---|---|---|
| 端口声明 | `input` / `output` | ANSI 风格写在头部括号里 |
| 网络与变量声明 | `wire` / `reg` / `logic` | 直接平铺，不需要再套块 |
| 参数 | `parameter` / `localparam` | |
| 并发语句 | `assign` / 例化 / `always` / `initial` | 同时存在，不是顺序执行 |
| 任务与函数 | `task` / `function` | 写大项目才用 |

**模块体本身就是一个块**，所以 `wire`、`assign`、例化都直接写，只有 `initial`/`always`/`if`/`case`/`task`/`function` 才需要自己的 `begin ... end`。

## 端口的三要素

```verilog
input  [3:0] a
 ↑       ↑    ↑
方向    位宽  名字
```

### 方向
`input`（进）、`output`（出）、`inout`（双向，几乎不用）。

### 位宽 `[3:0]`

**这不是一个数，是四根线捆成的一束。**

```
          a[3]  a[2]  a[1]  a[0]
   a  =  [    ][    ][    ][    ]
```

- 写法 `[高位:低位]`，通常左大右小
- 数字是**编号**不是个数：`[3:0]` 是 3、2、1、0 四个编号 → 4 位
- 省略位宽 = 1 位

**端口不是"一个引脚"，而是"一组引脚"**——这是硬件语言和软件语言最大的分野。软件里 `int a` 是一个数，硬件里 `[3:0] a` 是四根物理导线。

### 位选 `a[0]`

从一束线里取出其中一根。`full_adder` 的 1 位端口接 `adder4` 的 `a[0]`，位宽刚好对上。

**位宽必须匹配**：1 位接 4 位直接报错；4 位接 1 位会高位补 0，可能不报错但行为不对。

## `wire` 是什么

**一根有名字的导线。**

起名字的唯一目的是**能在多处引用同一根线**——例：4 位加法器里 `c1` 既接 `u0` 的 `cout`，又接 `u1` 的 `cin`。

```verilog
module adder4 (...);
    wire c1, c2, c3;      // 三位内部的进位线

    full_adder u0 (... .cout(c1));
    full_adder u1 (... .cin(c1), ...);
endmodule
```

为什么是 3 根不是 4 根：4 个全加器之间只有 3 个间隙。`cin` 和 `cout` 本身是端口，直接接，不用再起名。

不声明会怎样：Verilog 自动造隐式 wire，编译通过。但**拼错名字时灾难**——`c1` 打成 `cl`，它默默造一根新线，连接断开，仿真全 `x`，还要满世界找原因。

## 例化：不是函数调用

```c
int r = add(1, 2);        // 软件：执行一次，算完返回，栈帧销毁
```

```verilog
full_adder u0 (.a(a[0]), ...);   // 硬件：摆一个器件，从此一直存在
```

| | 函数调用 | 例化 |
|---|---|---|
| 什么时候发生 | 运行时，每调一次执行一次 | 编译/综合时，图纸上多一个元件 |
| 存在多久 | 执行完就没了 | 一直在，直到断电 |
| 有几个 | 同一时刻只有一个在跑 | 例化 4 次就有 4 个，**同时工作** |
| 返回值 | 有 | 没有，信号从端口持续流出 |

**「同时」是全部要害。** 4 个 `full_adder` 是 4 个独立电路，`a` 一变 `u0` 立刻反应，`u0` 输出一变 `c1` 立刻变，`c1` 一变 `u1` 立刻反应——**信号在电路中传播，不是程序逐行执行**。

### 命名端口连接

```verilog
full_adder u0 (
    .a(a[0]), .b(b[0]), .cin(cin),
    .sum(sum[0]), .cout(c1)
);
```

- `full_adder` 模块名（必须一字不差）
- `u0` 实例名（自己起，同模块内不能重名）
- `.a(...)` 点号后是**被例化模块内部**的端口名，括号里是**当前模块**的线
- `);` 分号结束语句

位置连接也能写（`full_adder u0 (a[0], b[0], cin, sum[0], c1);`），但顺序记错就全错且看不出来。**永远用命名连接。**

### 层次结构

```
tb_adder4                 ← 顶层（测试台）
└── adder4
    ├── full_adder u0
    ├── full_adder u1
    ├── full_adder u2
    └── full_adder u3
```

一颗芯片几亿个门，就是这么一层层例化出来的。以后 `cpu` 会长成 `alu` → `adder32` → `full_adder ×32` 的样子。

## 顺序规则

| 条目 | 顺序重要吗 |
|---|---|
| `wire` 声明 | **重要**——必须先声明后使用 |
| `assign` 之间 | 不重要（并发） |
| 例化之间 | 不重要（同时存在） |
| `always` 块之间 | 不重要（同时运行） |

所以四个 `full_adder` 的例化顺序可以打乱，电路**一模一样**——它们描述的是"同时存在的四个器件"，不是"按顺序执行的四步"。

## 我第一次搞错的地方

- 以为 `module adder4 ( ... );` 那个 `);` 就是模块结束，于是看不懂后面为什么还有内容。
- 把 `c3` 写成 `c[3]`——**`c3` 是一根叫 c3 的线，`c[3]` 是取向量 c 的第 3 位**。`c` 根本没声明，于是又触发隐式 wire。
- 把端口名 `.cin` 写成 `.c`。命名连接必须一字不差，否则编译器找不到端口。

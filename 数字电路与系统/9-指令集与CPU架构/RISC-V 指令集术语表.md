# RISC-V 指令集术语表

## 一句话

读 RISC-V 手册卡住的地方，九成不是语法，是这二十来个词。

## 为什么需要它？

RISC-V 非特权手册第 2 章（RV32I 基础整数指令集）八成篇幅是图和表，剩下两成英语句子反复用同一批词。把这批词认熟，剩下的就是看图。

而且这批词不止用于读手册——W10 开始写五级流水 CPU 时，控制单元的每个信号都对应这里的一个概念（`opcode` 决定走哪条通路、`funct3` 决定 ALU 干什么、`rd`/`rs1`/`rs2` 决定寄存器堆怎么接）。

## 一、字段类：32 位里每一位归谁

| 英文 | 中文 | 说明 |
|---|---|---|
| opcode | 操作码 | 最低 7 位 `[6:0]`，决定属于哪一类指令 |
| rd | 目的寄存器 | 结果写到哪个 `x` |
| rs1 / rs2 | 源寄存器 1 / 2 | 从哪两个 `x` 读 |
| funct3 / funct7 | 功能码 3 位 / 7 位 | opcode 相同、操作不同时用来区分（`add` 与 `sub` 只差 funct7） |
| immediate | 立即数 | 编码里直接给出的常数 |
| bit field | 位域 | 一个字里某几位属于谁 |

六种格式（R / I / S / B / U / J）的唯一区别就是**这几种字段的排列顺序和有无立即数**。R 型没有立即数，I / S / B / U / J 各自把立即数塞在不同位置。

## 二、动作类：指令在干什么

| 英文 | 中文 | 说明 |
|---|---|---|
| sign-extend | 符号扩展 | 12 位立即数 → 32 位，高位补符号位 |
| zero-extend | 零扩展 | 高位补 0 |
| truncate | 截断 | 高位丢掉 |
| branch | 分支 | 条件跳转（`beq` / `bne` / `blt` / `bge` / `bltu` / `bgeu`） |
| jump | 跳转 | 无条件（`jal` / `jalr`） |
| link | 链接 | 把返回地址存进 `rd`（`jal x1, …` 里的 `x1` 就是返回地址寄存器） |
| effective address | 有效地址 | `rs1 + imm`，访存时用它 |
| little-endian | 小端 | 低字节放低地址；`lw` 从内存读 4 字节时按这个顺序拼 |
| aligned / misaligned | 对齐 / 不对齐 | 地址是不是 4 的倍数 |

## 三、修饰类：决定这句话要不要认真读

| 英文 | 中文 | 说明 |
|---|---|---|
| shall / must | 必须 | 强制性要求，**只有带这个词的句子要精读** |
| may | 可以 | 允许但不必实现（伪指令、hint 常这么写） |
| reserved | 保留 | 现在不许用，将来可能定义 |
| hint | 提示 | 合法但硬件可以当 `nop` 处理（如 `addi x0, x0, 1`） |
| pseudoinstruction | 伪指令 | `nop` / `li` / `mv` / `j` / `ret` / `beqz`，汇编器展开成真实指令 |

## 四、句子的固定套路

手册的英文是规范体，结构高度重复：

> "The instruction **X** does **Y**. The **Z** field **shall** be set to **0**."

翻译过来就是"**X** 指令做 **Y** 这件事；**Z** 字段**必须**填 0"。

读的时候只抓三段：**主语（哪条指令）+ 动作（干什么）+ shall 后面的约束**。中间那种 `which is defined as ...`、`in the case of ...` 一律跳过——它们是给实现者写 RTL 时查的细节，不是理解时必需的。

## 五、英文版和中文版怎么配合

| 内容 | 用哪本 |
|---|---|
| 理解概念（寄存器是什么、格式怎么分） | 中文版，扫一遍，不纠结 |
| **六种格式的位图、opcode 表、立即数拆分图** | **英文版**（最权威） |
| 编码练习、查某条指令 | 英文版，只看表 |
| 规范用语（`shall` / `may` / `reserved`） | 英文版，只抓 `shall` 那句 |

两本的图对不上时一律以英文版为准。另外英文合订本的 PDF 页码和手册正文印的页码不一致，**引用一律用章号定位**（"第 2 章 2.2 节"），不要用页码。

## 六、读完自检四问

1. `add x5, x6, x7` 的 32 位是什么？
2. `lw x5, 8(x6)` 和 `sw x5, 8(x6)` 的编码差在哪几个字段？
3. `beq x1, x2, 8` 里那个 `8` 在机器码里被拆成哪两段？为什么这么设计？
4. `jal x1, 100` 的 `100` 是绝对地址还是偏移？存进去时要不要除以 2？

四问全中，RV32I 这一章算过关。卡在第 3、4 问，回去把 2.3 的立即数拆分图重画一遍。

## 我第一次搞错的地方

- 以为 `funct7` 是每条指令都有的——其实只有 R 型有，I / S / B 型那 7 位是立即数的一部分。
- 以为 `jal` 的偏移是绝对地址——是**相对 PC 的偏移**，而且编码时**最后一位恒为 0**（指令地址必然是 2 的倍数），所以范围是 ±1 MiB 而不是 ±512 KiB。

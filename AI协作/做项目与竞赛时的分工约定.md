# 做项目与竞赛时的分工约定

## 一句话

做项目和竞赛时，AI 只当教练不当替手：讲原理、给骨架、定验收标准、事后 review；**代码和设计必须我自己写**——学东西的过程本身是目的，不是可以外包的成本。

## 为什么需要它？

2026-11-09 第一次开工（W01 四位加法器），我一句「开始做本周项目」，AI 就把 `full_adder.v`、`adder4.v`、testbench、Makefile 全写好了，只留一步手工操作给我。结果是：目录建好了、逻辑验证过了，**但我一个模块都没写**。

这不是效率问题，是目标问题。这张 2026–2028 的时间表是为了复试时能讲清「这个 CPU 是我一行行调出来的」；如果代码是 AI 写的，那几百小时换回来的是一个能跑的仓库和零能力，而且我根本答不出「为什么 `cout` 写成 `(a&b)|(cin&(a^b))` 而不是三项或」这种三秒钟就能问倒我的问题。

面试官不看我有没有仓库，看我解释得清不清楚。解释能力只能从自己踩过的坑里长出来。

## 三条边界

| | 内容 |
|---|---|
| **不做** | 写我的 RTL / testbench / 脚本；我卡住时直接给能跑的代码；替我决定设计取舍；替我做必须亲手经历的操作 |
| **做** | 讲原理、画结构、说清验收标准；我写完后 review，指出哪行错、为什么错，但不重写；卡住时给方向不给答案 |
| **例外** | 我明确说「这个你来写」；以及项目之外的杂事（整理笔记、维护时间表、修工具脚本），那些不涉及能力训练 |

## 判据

判断一次「帮忙」算不算代做，只看一条：**把 AI 的产出删掉，我还能不能从零复现？**

- 能复现 → 那是资料、是提示、是 review，收下
- 不能复现 → 那是代做，退回去

这条比列清单好用，因为代做很少以「代做」的形式出现，它总是打扮成「帮你省点时间」。

## 执行方式

1. 每项任务 AI 只给「目标 / 约束 / 验收标准 / 卡壳时的提示层级」，不给成品
2. 我写完贴给它，它先问「你自己觉得哪里最可疑」，再指出问题
3. 调试时给的是「去看哪个信号的哪个时刻」，不是「把第 12 行改成 xxx」
4. 每周复盘里固定一条：**这周有多少行是我自己写的**

# testbench 与验证思维

## 一句话

tb 是验芯片的**台架**，不是电路——它永远不会变成硬件，只活在仿真器里。

## 为什么需要它？

因为**编译通过 ≠ 电路正确**。

`iverilog` 只查语法（拼写、分号、括号配对），不查逻辑。`cout` 里写 `&` 还是 `|`，编译器一律放行，两者都能编译通过。

芯片做出来之后不能"打开看看"，唯一的验证手段就是在仿真里喂激励、看响应。没有 tb，连第一步都走不了。

## 直观理解

`testbench` 字面是**测试台架**。硬件工程师的 bench 是一张工作台：

| 台架上的东西 | tb 里对应 |
|---|---|
| 被测芯片 | `full_adder uut (...)` 例化 |
| 信号发生器 | `reg a, b, cin;` + `initial` 里赋值 |
| 示波器探头 | `wire sum, cout;` + `$display` |
| 按剧本操作的机械手 | `initial begin ... end` |

**图纸变成硅片，台架留在实验室。**

## 可综合 vs 不可综合

同一个 `module` 关键字，能写两种完全不同的东西：

| | 可综合（RTL） | 不可综合（tb） |
|---|---|---|
| 里面写什么 | `assign`、`always @(posedge clk)` | `initial`、`#10`、`$display`、`$finish` |
| 描述什么 | 电路**长什么样** | 时间上**发生什么** |
| 能变硬件吗 | 能，`yosys` 综合出门电路 | 不能 |
| 有端口吗 | 有（要被别人用） | 没有（它是最外层） |

`#10` 在真实电路里**不存在**——没有哪个门能"延迟 10 纳秒然后动一下"，延迟由物理寄生参数决定。`$display` 更荒谬：芯片上没有"打印到终端"这个动作。

所以区别**不在语法，在内容**：一个 module 里一旦出现 `initial`、`#`、`$display`，它就是 tb。

（极端例外：FPGA 里常见 `initial begin reg_file[0] = 0; end` 给寄存器上电赋初值，ASIC 里不行，但 FPGA 能接住。）

## 完整骨架（1 位全加器，已跑通）

```verilog
`timescale 1ns/1ps

module tb_full_adder;

    reg  a, b, cin;        // 输入 → reg，因为要赋值
    wire sum, cout;        // 输出 → wire，由 DUT 驱动

    full_adder uut (       // 例化：放器件 + 接线
        .a(a), .b(b), .cin(cin),
        .sum(sum), .cout(cout)
    );

    initial begin
        a = 0; b = 0; cin = 0; #10;
        $display("a=%b b=%b cin=%b -> sum=%b cout=%b", a, b, cin, sum, cout);

        a = 0; b = 0; cin = 1; #10;
        $display("a=%b b=%b cin=%b -> sum=%b cout=%b", a, b, cin, sum, cout);

        // ... 共 8 组，按 000 001 010 011 100 101 110 111 顺序

        $finish;
    end

endmodule
```

### 逐行要点

| 行 | 要点 |
|---|---|
| `` `timescale 1ns/1ps `` | 时间单位 1ns、精度 1ps。开头是**反引号**（Esc 下面那个键），不是单引号 |
| `module tb_full_adder;` | **没有端口列表**。端口是"给外面接的地方"，tb 是最外层，没有比它更外面的 |
| `reg a, b, cin;` | tb 要主动赋值 → 必须 `reg`。写 `input` 没意义（没端口） |
| `wire sum, cout;` | 被 DUT 驱动 → 只能 `wire`。写 `sum = 1;` 会报错 |
| `full_adder uut (...)` | **例化**：放一个器件，把线接上去。不是函数调用 |
| `.a(a)` | 左边点号后是 DUT 内部端口名，括号里是 tb 的线。写成 `.a(b)` 能编译但结果全错 |
| `initial begin ... end` | 仿真一开始执行**一次**。`end` 后不加分号（块不是语句） |
| `#10` | 等 10 个时间单位。给组合逻辑传播时间，不等会打印到上一组的结果 |
| `$display(...)` | `$` 开头是系统任务。`%b` 二进制，占位符与参数**按顺序**一一对应 |
| `$finish;` | 结束仿真。不写会一直挂着不退出 |

### 跑法

```bash
iverilog -o tb.vvp tb_full_adder.v full_adder.v
vvp tb.vvp
```

**第一个文件是顶层**（仿真起点），被例化的模块放后面。

## 验证的三个层次

### 第一层：穷举 + 肉眼看
8 种输入全试，`$display` 打印，对着真值表核对。能覆盖全部情况，但**靠眼睛判断**——512 行、8000 行时人必漏。

### 第二层：定向测试
不穷举，专挑最疼的：全 0、全 1、只有一个 1、进位链最长的 `111 + 1`。做 32 位 CPU 时 2^32 不可能穷举，只能定向 + 随机。

### 第三层：随机 + 自动比对（工业界做法）
随机生成输入，同时用"金标准模型"算期望输出，**自动比对**，不等就打印 `FAIL` 和具体哪一组，最后打印 `PASS 512/512`。

**判断权从人眼转移到代码。** 这是验证工程的核心思想——人不可靠，机器可靠。

### 代价的现实

真实芯片公司里**验证工程师和设计工程师是两种岗位**，人力比常是 2:1 甚至 3:1。一颗 CPU 的代码量里，RTL 占 30%，验证环境占 70%。

所以这不是"附带步骤"，是一条独立的职业路径。

## 我第一次搞错的地方

- 把命令 `vvp` 和文件名后缀 `.vvp` 混为一谈。`vvp` 是**可执行程序**（`/usr/bin/vvp`），`.vvp` 只是 `-o` 后面自己起的文件名，叫 `tb.abc` 也能跑。写成 `vpp` 就是 `command not found`。
- 在 `$display` 的格式串里用中文输入法的 `→`（U+2192）。字符串里能编过，但代码里只用 ASCII 最安全；`->` 就是减号加 Shift+句号。
